# rf-cities

獨立的逆統戰據點戰地圖，顯示城市控制權、聯盟與即時戰況。

Oracle 常駐採集 → Supabase 公開快照與即時通知 → GitHub Pages。
不需要遊戲模組，也不需要自己的電腦或遊戲画面保持開啟。
遊戲權杖、Supabase 寫入金鑰只保存在採集主機，不可提交到 GitHub。

部署見 [BACKEND.md](BACKEND.md)，SQL 見 [supabase/setup.sql](supabase/setup.sql)。
本機：設定 `.env` 後 `npm start`，開啟 http://127.0.0.1:8787 。
測試：`npm test`，不登入遊戲、不向線上資料庫發送測試戰況。

歷史長期封存：Oracle 自動保存至 `.data/history-archives/`，不跟隨 Supabase 的近期紀錄清理；仍需自行做異地備份。GitHub Pages 自動讀取還需公開的 HTTPS 封存出口或發布 `archives/` 靜態檔案，詳見 [BACKEND.md](BACKEND.md) 的「Oracle 長期歷史封存」。

## 地圖與路線規劃

### 排行、控制區、縮時與戰報

- 選單或手機底部列可開啟陣營／聯盟排行、縮時與設定。排行依有座標的城市計數，以聯盟 ID 分組，同名不同 ID 不合併；點項目篩選地圖，「顯示全部」取消。
- 設定可切換控制陣營／控制聯盟色塊及透明度。色塊是有界 Voronoi 示意，距城市最多 500 底圖單位，非官方領土邊界，可能涵蓋海域；不知道控制方的城市不推測。控制權改變時立即換色。
- 歷史時間軸以臺灣日期選快照，1×～64× 播放；每次前進一個真實快照，不插值。歷史模式不覆寫即時清單、不停止採集；「回到即時」恢復最新清單。歷史圖上的倒數依該快照時間，不依現在時間。
- 本機紀錄只涵蓋本頁開啟、資料新鮮且發生變更的時段，最多每分鐘一次，保存最近 60 個快照（最多約 1.8 MB）。儲存被封鎖時仍可播放本次記憶體紀錄並匯出。
- 全天候雲端歷史**需另外執行 `supabase/history.sql`，尚未執行就不會保存**。SQL 從現有 Oracle 發布的快照記錄控制權，不須重啟 Oracle。僅存公開城市、陣營、聯盟，無歷史戰鬥比分。每分鐘至多一個快照，發生變化或臺灣新一天時記錄；下一次寫入時清理超過 7 天或 2000 個的舊快照。仍會消耗免費資料庫配額。啟用前的歷史無法補回。
- 匯出所選日期的本站 JSON 戰報、控制权變化 CSV，或匯入本站 JSON 播放；不保證相容其他網站格式。JSON 只保留白名單公開欄位，匯入不寫入雲端；CSV 避免公式注入。控制變化不是逐場勝負判定。

### 自己修改底層路線

「左上角選單 → 路線編輯器」可直接編輯白色實線鐵路、白色虛線土路及設定中開啟的黃色虛線機場遷移；與黃色實線的個人路線規劃分開。土路從橘色改為白色虛線、機場統一改為黃色虛線，只影響呈現，不改動路線幾何及既有草稿。

2026-10-11 已以使用者最新提供的 `reference-route-geometry-edited.json` 原檔完整取代目前 `reference-route-geometry.json`：279 條鐵路、177 條土路、23 條機場路線，共 479 條。保留全部座標、曲線與種類，不重跑舊描圖器。以下描圖記錄僅為歷史來源，不代表現在仍採用舊版幾何。新基準會使舊瀏覽器草稿不再自動套用；舊草稿仍可匯出備份，避免蓋過這份路線。

1. 搜尋城市或縮放到欲修正區域，點線選取。拖曳綠色端點／折點；原生曲線另外提供黃色彎度控制點。端點距離城市 14 個螢幕像素內會吸附並記錄固定城市 ID。
2. 錯線可「刪除所選」。折線可「改成曲線」再調整彎度；此操作會取代中間原形，需確認且可復原。
   「多選」模式可逐條點選／再點取消，選線全部以綠色凸顯；「取消選取」清空選取。可一次刪除或在路線種類選單批次修改，每次批次操作算一個復原／重做步驟。混合種類會顯示「多種路線，請選擇」。多選不拖動線形，切回「選線／調整」只保留最後選取的一條線。
3. 「新增線」選種類，依序點城市或空白處，按「完成新增」。完成後維持新增模式、清空當前節點並取消選取，可直接點另一條獨立線的新起點，不會接上上一條。再次按「新增線」也會重新開始一條線；種類維持目前選擇。要調整或改成曲線，先切回「選線／調整」再點選。切換「移動地圖」可拖曳平移／雙指縮放；滾輪與縮放按鈕一直可用。
4. 草稿自動保存在此瀏覽器，不上傳、不跨裝置同步，不停止即時採集。「復原」最多保存本次開啟的 12 次變更，「重做」可恢復剛才復原的操作（含新增中的節點）；復原後做新的修改會清除重做紀錄。「還原網站路線」也可復原。復原／重做紀錄不跨重新整理保存。
5. 定期「匯出備份」，下載 `reference-route-geometry-edited.json`；另一台裝置使用「匯入路線檔案」。要公開發布時，把匯出檔案交給维护者核對、取代 `reference-route-geometry.json` 並部署。編輯器本身沒有雲端寫入金鑰及發布能力。

網站原始路線版本變更時，不會自動覆蓋式套用舊草稿：編輯器提示並允許先匯出舊草稿，再自行匯入或還原。瀏覽器保存失敗會顯示立即匯出提醒。匯入驗證座標尺寸、路線種類、有限數值及資料大小。修改不會重新執行圖片描取。發布手動修改後，也不要用舊描圖工具重新覆寫人工修改檔案。

- 2026-10-09 臺灣區域獨立人工重描：`taiwan-routes-source.json` 保存原圖控制點與固定城市 ID；`build_taiwan_routes.py` 產生原生三次曲線，精確接合城市端點。16 段白色環線／臺中支線，5 段島內土路、5 段連外土路（含澎湖→高雄、佬沃→屏東、東沙→屏東）。不包含錯誤的基隆→新北白色線或苗栗→臺中支線。描圖器會自動套用人工修正，避免重跑後復發。區域外原有幾何與機場層保留。
- 「選單 → 路線規劃」可手動畫途經點，或展開「依現有路線自動規劃」選起終點與路線種類。預設勾選機場並採「機場優先」：先比較地面線長，再比較機場遷移段數，最後比較總線長；不是盲目增加機場段數。沒有機場捷徑時仍可走地面路線，取消機場勾選就不使用機場；亦可手動選「總線長最短」沿用原本排序。只在城市端點接合，不在交叉點轉乘，缺路不以直線補接。不代表已驗證的遊戲通行／遷移資格，地面線長僅是比較用的底圖單位，尚無遊戲能量公式，不能宣稱最低能量或精確移動時間。手動規劃及已存草稿不會自動重算。
- 規劃時仍可拖曳、縮放；暫停畫線後可查看城市。支援復原、重做、刪除／前後移動途經點、反轉順序及規劃 JSON 匯入匯出。手動調整途經點會回到直線模式，不沿用已失效的自動路徑；清除也能復原。原有規劃與路線編輯草稿不刪除。
- 路線只保存到目前瀏覽器的 localStorage，不上傳、不跨裝置同步，也不影響採集更新。清除瀏覽器網站資料會移除保存路線。
- `python build-reviewed-routes.py` 依固定 ID 編譯人工記錄，不使用像素門檻、距離或最近城市補線；尚未對應的端點列入 unresolved，不強行對應。只在開發時執行，網站及 Oracle 不執行此工具。
